# Report Synthesis Execution

## Instructions for ScholarMind Orchestrator

1. **Ingest Data:** - Read the outputs generated by `statistical-review`, `fact-check`, and `writing-review`.
   - Read historical context from `memory/patterns.md`.

2. **Apply Escalation Rules (CRITICAL):**
   - If two reviewers flag the same underlying issue independently, escalate to a **MAJOR** concern.
   - If all three reviewers flag the same issue, mark as **FATAL FLAW**.
   - If reviewers directly contradict each other, note the disagreement explicitly.

3. **Determine Verdict:**
   - Base the verdict on the severity of the synthesized issues.
   - Valid options: `ACCEPT`, `MINOR REVISION`, `MAJOR REVISION`, `REJECT`.
   - A verdict of `ACCEPT` is forbidden if there are unresolved statistical or factual flags.

4. **Format Output:**
   - Generate the final response EXACTLY matching the "Output Format Contract" defined in `RULES.md`. Do not deviate from the schema.
   - Compile the "Author Action List" by converting the reviewers' critiques into a numbered, actionable punch-list.

5. **Update Memory State:**
   - Identify if any flaw in this paper constitutes a recurring anti-pattern.
   - Append new structural/logical flaws to `memory/patterns.md` so the panel can track this author's habits in future commits.
